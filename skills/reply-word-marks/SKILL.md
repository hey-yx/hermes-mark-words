# 回复末尾的词标记块（::hmw）

hermes-mark-words 插件给回复里有疑点的词加标记（普通疑点是中性点线，疑似生造/含义不明是细红波浪线），悬停给解释和追问。标记关系由你在这条回复里直接给出，插件不再另行请求模型。

## When to Use（什么时候输出）

三条同时满足才输出：

1. Hermes 桌面端聊天里给用户看的最终回复（环境段 Platform: desktop）。
2. 正文里确实有「读者会存疑」的词，二选一即可（一个都没有就整块不输出）：
   - 疑似生造、可能不存在的说法；
   - 含义不明、用法有歧义、或被你自己临时造出来的概念；
   - 值得追问核实的说法里的关键说法。
3. 回复本身就是给用户看的正文。

**只标有疑点的，不标术语表。** 基本口径：

- 不标基础词、常识词、行业通行的标准术语（浏览器、下载、缓存、接口、API、数据库、p90、TTFB 这类含义明确的都算），哪怕它技术性很强；常规工程词（加载、路由、同步、备份、日志、部署、监控这类）同样不标。
- 两字纯汉字词只有「疑似生造 / 含义不明」档能标（插件闸门会拒术语档的两字词）；想标两字词就把疑点写进 kind。
- 不标正文里已经解释清楚的词，不标文件路径、命令、代码标识符、版本号、纯数字。
- 一段回复通常 0 到 3 个词；一个够格都没有就整块不输出，绝不凑数。
- **不限语言**：回复是中文、英文、日文、韩文还是混合，都按同一口径挑；term 原样取那个语言的写法。

一律不输出：非 desktop 平台（消息平台、CLI 管道、cron）、工具调用结果、被其他代理消费的中间产物（子任务总结、看板交接）、看板卡片、PR、issue、提交信息、文件内容、代码。

## 格式

正文写完后，末尾另起一段（与正文空一行）。**每条指令单独成段，指令之间必须空一行**：宿主只把「整段就是一个 ::name{...}」的段落渲染成组件，连续两行挤在同一段里会被当成普通文字原样显示：

::hmw{term="原文里的连续片段", kind="unclear", explain="这个词在这段话里指什么、是干嘛用的、跟他有什么关系，60 字以内", note="不确定处或来源提示，没有就省略本字段", q1="针对该词语境的具体追问"}

::hmw{term="第二个词", kind="fabricated", explain="…", q1="…"}

（上面两条之间那个空行不是排版偏好，少了它整块指令会出现在对话正文里。）

- term 逐字取自正文（含大小写与原文语言），2 到 24 字，不改写不翻译。
- kind 取 fabricated（疑似生造）、unclear（含义不明或有歧义）、term（用法不标准、值得商榷）之一；存疑为主，term 只是兜底。
- explain 必须就着上下文回答「它在这段话里指什么、是干嘛用的、跟他有什么关系」，不写百科式定义；含义真判断不出来就明说「从上下文看不出它指什么」再讲哪里可疑，不要硬编。
- 属性值里禁止出现双引号、花括号、换行；解释里引用别处说法用「」。值本身带双引号时改用单引号包裹整个值。
- q1、q2 是可选追问，针对这个词在这段语境里的疑点，能落地核实；0 到 2 条：只给 1 条、或者一条都不写都正常，没有能落地的追问就不写 q 字段，绝不凑 2 条。（q3 解析仍兼容，一般用不到。）
- 每个词一条指令，最多 3 条；指令之间空一行。宁缺毋滥：没有够格的词就一条都不输出，绝不凑数。
- 标记块必须是回复的最后一部分，块后不再有任何文字。
